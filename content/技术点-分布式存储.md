### B1.1 Raft 一致性协议

| 字段 | 内容 |
|---|---|
| 是什么 | Leader 选举、日志复制、安全性、成员变更、脑裂处理；etcd 的生产级实现。 |
| 为什么学 | 一切分布式存储的地基。阿里云 OSS 校招 JD 明确"攻克超大规模集群管理及一致性协议"，并把"读过 Ceph/RocksDB/etcd 源码"列为加分[38]；PingCAP 存储引擎岗要求了解 Raft/Paxos、分布式事务[39]。 |
| 怎么学 | Raft 可视化动画先建直觉[34] → Raft 原论文[35] → Raft 官网索引[36] → etcd 官方文档看生产落地[37]。 |
| 可验证产出 | 白板能讲清选举+日志复制+脑裂；用 Go 实现一个迷你 Raft-KV（见学习路线 Phase 1），单测通过、有 README。 |
| 对应岗位要求 | "攻克超大规模集群管理及一致性协议难题"[38]；"对 B+Tree、LSM-Tree……Raft/Paxos、分布式事务"有了解[39]。 |

### B1.2 分布式系统基础（DDIA）

| 字段 | 内容 |
|---|---|
| 是什么 | 复制、分区、事务、一致性模型、CAP、LSM/B-Tree；Martin Kleppmann 的《数据密集型应用系统设计》。 |
| 为什么学 | 所有分布式存储岗的共同语言；腾讯云要求"深入理解操作系统和网络基本原理"[65]。 |
| 怎么学 | DDIA 官网按目录读第 5（复制）、9（一致性与共识）、13（编码与演化）章[40]。 |
| 可验证产出 | 读完指定章节输出 ≥5 篇笔记；每篇含一个"我现职备份状态机里哪条规则对应这个概念"的对照。 |
| 对应岗位要求 | "深入理解操作系统和网络基本原理，具备扎实的数据结构和算法基础"[65]。 |

### B1.3 Ceph 架构总览

| 字段 | 内容 |
|---|---|
| 是什么 | RADOS、CRUSH 算法、PG、Monitor/OSD/MDS，以及 RBD（块）/CephFS（文件）/RGW（对象）三大接口。 |
| 为什么学 | Ceph 是开源存储事实标准，奕斯伟公开招"Ceph OSD/BlueStore/RADOS 核心模块开发、IO 路径定制"[43]；深圳底座岗 JD 点名"熟悉 Ceph（尤其 OSD/BlueStore/SeaStore）"[3]。 |
| 怎么学 | Ceph Beginner's Guide 入门[41] → Architecture Guide 读 CRUSH/Peering/EC[42]。 |
| 可验证产出 | 画出一张"客户端写一个对象，经过 RBD/RGW→OSD→CRUSH 落到哪个 PG"的路径图；单机用 cephadm 起最小集群并建一个 Pool。 |
| 对应岗位要求 | "负责 Ceph OSD/BlueStore/RADOS 等核心模块的代码开发、Bug 修复与性能优化……数据分布算法及 IO 路径"[43]。 |

### B1.4 BlueStore 存储引擎

| 字段 | 内容 |
|---|---|
| 是什么 | Ceph OSD 的本地存储引擎：RocksDB 管元数据、块分配器、BlueFS、写路径。 |
| 为什么学 | Ceph 数据面的核心模块，奕斯伟 JD 直接点名 BlueStore[43]；RocksDB 同时是 LSM 存储引擎的必读教材[44][45]。 |
| 怎么学 | RocksDB 官网入门 LSM 定位[44] → RocksDB Wiki 的 Understanding 系列[45] → 对照 Ceph Architecture 看 BlueStore 怎么用 RocksDB。 |
| 可验证产出 | 用 ldb/sst_dump 看一次 SST 文件；写笔记画清 MemTable→SST→Compaction 的写路径；能说清写放大量化口径。 |
| 对应岗位要求 | "Ceph OSD/BlueStore/RADOS 核心模块"[43]；深信服存储岗要求 RocksDB/Raft[46]。 |

### B1.5 Ceph IO 路径

| 字段 | 内容 |
|---|---|
| 是什么 | 一次客户端请求从 API 到 OSD 再到磁盘的完整流；副本写 vs 纠删码写；"一次写请求走多深"。 |
| 为什么学 | 这是面试高频题，也是"从控制面看进数据面"的核心动作；Ceph Developer Guide 讲 vstart 单机开发集群与单测[47]。 |
| 怎么学 | 在 B1.3/B1.4 基础上读 Ceph Developer Guide[47]，用 vstart 起开发环境。 |
| 可验证产出 | 画出"一次 RBD 写"完整路径图（客户端→ librbd → OSD → BlueStore → 磁盘），标注每层延迟量级假设；精读笔记 ≥5 篇。 |
| 对应岗位要求 | "针对业务场景定制……IO 路径"[43]；"深入理解 Linux I/O 栈"[66]。 |

### B1.6 块存储基础

| 字段 | 内容 |
|---|---|
| 是什么 | SCSI、块设备、IO 调度、RAID、iSCSI/NVMe 驱动栈。 |
| 为什么学 | 惠鑫天空高级存储岗要求"精通块存储原理，熟悉块设备驱动、I/O 调度、多路径、RAID、LVM、iSCSI/NVMe-oF"[48]；这是底座岗硬门槛。 |
| 怎么学 | 结合技术点-AI存储 A1.5 的 NVMe-oF 规范[20]，补 SCSI/块设备通识（公开教材/文档即可）。 |
| 可验证产出 | 笔记一张"SCSI 命令 → 块层 → IO 调度 → 驱动 → 设备"分层图；用 lsblk/sysfs 在本机观察一次块设备拓扑。 |
| 对应岗位要求 | "精通块存储原理，熟悉块设备驱动、I/O 调度、多路径、RAID、LVM、iSCSI/NVMe-oF"[48]。 |

### B1.7 对象存储

| 字段 | 内容 |
|---|---|
| 是什么 | S3 协议、分片上传、纠删码、桶与元数据；MinIO 是最流行的开源 S3 实现。 |
| 为什么学 | S3 是 AI 生态事实标准；阿里云分布式存储专家岗做"多 AZ 容灾、纠删码、数据恢复"[49]；AI 训练数据、模型文件、KV Cache 后端越来越多落在对象存储。 |
| 怎么学 | 单机部署 MinIO + mc 客户端，建 bucket、传对象[74]；读 handler 理解 S3 PUT 路径。 |
| 可验证产出 | 用 MinIO 完成一次分片上传并 curl 出对象；笔记讲清"一次 S3 PUT 从网关到磁盘"的路径与每层开销。 |
| 对应岗位要求 | "分布式存储系统中数据一致性协议……多 AZ 容灾，纠删码，数据恢复"[49]。 |

### B1.8 重删与压缩

| 字段 | 内容 |
|---|---|
| 是什么 | 指纹哈希去重、CDC 可变分块、LZ4/Zstd 压缩。 |
| 为什么学 | 这是你现职备份产品域的直接对口缺口。绿联备份岗要求深入 Linux 内核与文件系统、熟悉 SMB/rsync/S3 传输协议[50]；英方软件备份岗公开写"熟悉重删、带库、备份、存储优先"[51]。 |
| 怎么学 | 用公开资料整理原理（不涉及内部实现）：CDC 分块、指纹索引、压缩选型；可结合 MinIO/开源备份工具观察。 |
| 可验证产出 | 写一份《重删/CDP/应用一致性快照原理》公开技术笔记（≥2000 字），只用公开资料；用 zstd 实测一组文件压缩比并记录。 |
| 对应岗位要求 | "熟悉重删、带库、备份、存储优先"[51]；"熟悉 Btrfs、ZFS、ext4 原理，掌握 I/O 栈"[50]。 |

### B1.9 快照与克隆实现

| 字段 | 内容 |
|---|---|
| 是什么 | CoW（写时复制）vs ROW（读时重定向）两种快照实现；块级快照与增量链。 |
| 为什么学 | 你在现职做"快照状态机/失败回滚/增量链维护"，但那是控制面编排；补到实现层，才能把概念从"调度"补到"块设备上真发生了什么"。纽创信安防勒索备份岗要求"实时备份、快速恢复、攻击隔离"[52]。 |
| 怎么学 | 对照 Btrfs/ZFS/LVM 快照的公开文档理解 CoW/ROW；K8s CSI Changed Block Tracking（CBT）2026-09 进入 Beta 是行业信号（常识性判断，结合公开博客）。 |
| 可验证产出 | 在本机用 LVM/Btrfs 亲手打一个快照、改数据、从快照恢复；写笔记对比你做的"快照状态机编排"与"块级快照实现"的边界。 |
| 对应岗位要求 | "实时备份、快速恢复和攻击隔离"[52]；企业存储专家岗点名"快照、异步复制、数据重删"（公开 JD 口径）。 |

### B1.10 性能分析与调优

| 字段 | 内容 |
|---|---|
| 是什么 | fio 压测、perf、火焰图、eBPF/bcc、io_uring。 |
| 为什么学 | 这是你读研性能优化方法论（火焰图/perf 已认知）的直接迁移；美团基础架构岗优先"了解内核及文件系统、SPDK、io_uring 等底层 IO 技术"[56]。 |
| 怎么学 | fio 官方文档学 job file 写法[53] → Linux perf Wiki 的 Top-Down 方法[54] → iovisor/bcc 动态追踪[55]。 |
| 可验证产出 | 用 fio 跑出一份带 IOPS/吞吐/延迟曲线的报告；用 perf 或 bcc 对一个真实程序抓一次火焰图并定位一个热点；把读研"固定种子逐级精度对比"改写成《存储排障 checklist》。 |
| 对应岗位要求 | "了解内核及文件系统、SPDK、io_uring 等底层 IO 技术"（优先项）[56]。 |
