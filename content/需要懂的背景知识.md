### 1.1 三大存储类型

#### SAN‑块存储

- 对外提供裸磁盘 LUN，**文件系统由业务服务器安装管理**。
- 协议：FC、iSCSI、NVMe‑FC、NVMe‑RoCE、NVMe‑TCP
- 典型产品：OceanStor Dorado。适合数据库、虚拟机。

#### NAS‑文件存储

- 存储设备本身运行文件系统，走 IP 网络。
- 协议：NFS (Linux)、SMB (Windows)、HDFS。
- 高级能力：配额、WORM (写保护不可修改)、GVS 全局命名空间。
- 典型产品：OceanStor Pacific。适合文档、日志共享。

#### 对象存储

- 最小单元：Bucket 桶；基础接口 PUT/GET。
- 适合非结构化数据：图片、日志、音视频。
- 关键技术：全局命名空间、纠删码 N+M、多版本、加密、多活容灾。
- NAS + 对象网关：做协议转换，会引入额外时延。

### 1.2 通用存储术语

1. **Thin Provision 精简分配**：虚拟容量映射，物理空间随写入动态分配，提升存储利用率。
2. **QoS**：对带宽、IOPS、IO 优先级做管控，防止业务互相抢占资源。
3. **Dedupe 重复数据删除**：识别重复数据块，只存一份副本，备份场景收益明显。
4. **Snapshot 快照**：COW 写时复制，只复制映射关系，不是完整拷贝，创建快，占用空间小，是备份的前置能力。
5. **Replication 复制**：主 LUN→从 LUN，用于阵列层灾备。
6. **缓存分层**：RAM Cache → SSD/SCM Cache → SSD Tier → HDD Tier，冷热数据分层。

### 1.3 备份保护基础概念

- **RPO**：灾难发生后最多丢失多久的数据；代表数据丢失容忍度。
- **RTO**：故障后业务恢复完成需要多久；代表业务中断容忍度。
- 容灾优先级（从高到低）：**应用层 > 数据库层 > 网络层 > 阵列层**。排障、方案设计优先看上层。
- 备份类型
    - 全量：拷贝全部有效数据
    - 增量：拷贝上一次备份之后变化的数据块
    - 差异：拷贝上一次全量之后变化的数据块
- 归档：冷数据长期保存，用于合规留存，不用于高频恢复。

### 1.4 HCS 资源模型

- **租户**：顶层账号，最高权限。
- **O‑VDC（组织 VDC）**：绑定租户 ID，组织层级，用于组织 / 部门资源归类。
- **I‑VDC（项目 VDC）**：实际业务资源池，存放 ECS、磁盘卷；租户可以管控下层全部 I‑VDC。

### 1.5 OP & Agent 基础概念

1. **OP(OceanProtect)**
    - OP**本身不存业务数据**，只做调度、管理、任务下发、结果汇总。
    - 部署：K8s 容器化，业务以 Pod 运行。
    - 三方角色：OP 调度端、Agent 客户端、HCS 存储端。
2. **Agent 客户端代理**
    - 运行插件`AppPlugin_VAS`，**真正执行业务逻辑、调用 HCS 接口**。
    - 两种部署模式：内置 Agent / 外置 Agent (VHA)

| 项目     | 内置 Agent                  | 外置 Agent (VHA)                   |
| ------ | ------------------------- | -------------------------------- |
| 部署位置   | OP 本机 Pod 内               | 独立外部主机                           |
| 业务执行日志 | 落在 OP 机器                  | 落在外置主机；OP 只存 PM 调度日志             |
| 域名映射   | Agent 侧做域名映射，OP 不用改 hosts | OP 本机 hosts 做域名映射；无 hosts 则走 DNS |
| 连通要求   | OP 不需要 ping 通客户端          | OP 需要能够 ping 通客户端主机              |

> 生产链路
> 
> - 内网 DNS → 内置代理 → 存储
> - 外网 DNS → 外置代理 (VHA) → 存储

### 1.6 网络基础概念

- **管理网**：注册、指令下发、控制信令、心跳。
- **备份网**：海量备份数据流传输，大带宽。
- **复制网**：复制 / 容灾同步流量。
- 五大网段：归档、备份、管理、复制、业务，**必须隔离，不能冲突**。
- Bond/Eth‑Trunk：网卡链路聚合；LACP/M‑LAG 为协议；交换机堆叠做高可用。
- NTP：UDP 123，集群节点时间必须对齐，否则任务、快照链、日志全部异常。
- DNS 解析：HCS 证书校验强依赖域名；ping 通 ≠ DNS 解析正常 ≠ 业务通。

### 1.7 VHA 双活基础

VHA 是 HCS 的虚拟机双活能力，一台虚拟机同时运行在两套存储，分为**主端、容端**。

- 原有备份流程没有 VHA 识别逻辑；快照下发依赖 LUN；ID 链路长：VM‑ID →卷 ID → LUN。
- 改造目标：识别 VHA 实例，区分主 / 容端，正确拿 LUN，做快照，区分全量 / 增量备份。
